# ممیزی مبنا — نسخه ارسال‌شده پیش از اصلاح

منبع: `audit-trail-api-ready.zip`. نسخه اصلی جداگانه حفظ شده است.

## بررسی اجرا
- Node.js v22.16.0 / npm 10.9.2
- `npm ci --offline`: موفق
- `npm test`: 45/45 موفق؛ این عدد عدم وجود نقص را ثابت نمی‌کند.
- تست دستی درخواست JSON با `actorId` تکراری: 201 و ثبت مقدار دوم.
- تست دستی تغییر غیرمجاز `actor_id` با اتصال SQLite پس از حذف Trigger محافظ: `GET` پاسخ 200 و مقدار جعلی؛ `store.verify()` مغایرت هش را تشخیص داد.

## یافته‌ها
| شناسه | اهمیت | یافته | اقدام |
|---|---|---|---|
| B01 | بالا | API بعد از دست‌کاری بیرونی داده تغییرکرده را می‌خواند | تشخیص تغییرات بیرونی با `PRAGMA data_version` و توقف دائمی سرویس تا بررسی و بازراه‌اندازی مورد اعتماد |
| B02 | بالا | JSON دارای کلید تکراری و UTF-8 نامعتبر مبهم ثبت می‌شود | رمزگشایی UTF-8 به‌صورت strict و رد کلید تکراری در همه سطوح |
| B03 | بالا | حذف دم زنجیره بدون Head مرجع بیرونی از طریق Verify قابل تشخیص نیست | Checkpoint جداگانه برای تأیید Prefix با توضیح مرز اعتماد |
| B04 | متوسط | Schema پیش از ارزیابی `user_version` تغییر می‌کند | کنترل نسخه پیش از هر DDL، تراکنش اتمیک و راستی‌آزمایی اجزای v1 |
| B05 | متوسط | رشد بدون سقف رکورد و حافظه عملیاتی | سقف پیکربندی‌شده برای تعداد رویدادها و پاسخ صریح هنگام اشباع |
| B06 | متوسط | نبود آزمایش مستقل Failure Modes و ورودی‌های مبهم | تست رگرسیون و سناریوهای منفی قابل تکرار |
| B07 | استقرار | HTTPS، محدودسازی نرخ، هویت کاربر نهایی و Rotation کلید خارج از پروژه | حفظ محدوده صادقانه؛ مستندسازی کنترل‌های لازم در Ingress و سرویس مبدا |

## مرزهای امنیتی
- داشتن کنترل کامل روی فایل دیتابیس / سیستم‌عامل فراتر از امنیت قابل ارائه در یک پروسه Node.js است.
- SQLite Triggerها جلوی عملیات SQL معمولی را می‌گیرند، نه تغییرات مدیر دیتابیس.
- checkpoint تنها زمانی در برابر تغییر تاریخچه قابل اتکاست که در محل مستقل و مورداعتماد نگهداری شود.
